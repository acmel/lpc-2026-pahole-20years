Compilable output: fullcircle



  $ pfunct --compile file.o > file.c   # C from DWARF
  $ CFLAGS=$(readelf -wi file.o | grep DW_AT_producer ...)
  $ gcc $CFLAGS -c -g file.c -o file2.o
  $ codiff -q -s file.o file2.o        # silent: same types
  • Binary → C → binary: types survive the round trip
  • Script fullcircle in the pahole tree, used in CI

DWARF is a moving target


  • Compilers: gcc, clang, rustc...
  • Versions, vendors, distro packaging
  • Standards evolve: DWARF 2..5, 6 coming
  • Same source, different DWARF

Old tools, new BTF


  • AlmaLinux 8 containers: bpftool v4.18.0
  • No .bss DATASEC, no VAR in its dumps
  • bpftool v7.5+: correct
  • Not a pahole bug: skip, and say why

if echo "$dump" | grep -q "DATASEC '\.bss'"; then
    check_bss_variable
else
    info_log "skip: bpftool doesn't display .bss DATASEC"
fi
Merged from two cases: missing .bss DATASEC and missing VAR entries in old bpftool dump output. Both: the BTF is right, the old tool cannot display it. Detect, skip, say why.

DWARF decides what you see



typedef _Atomic int atomic_int;
struct test { atomic_int x; };

gcc -gdwarf-5 -c test.c
  • clang 21.1.8: typedef → base_type, no atomic node
  • gcc/clang 22+: typedef → DW_TAG_atomic_type
  • Both correct: pahole reads DWARF, not source
  • DWARF version varies by distro: force -gdwarf-5

--reorganize: naïve packing



  $ pahole -R --show_reorg_steps -C demo demo.o
  /* Moving 'd' from after 'c' to after 'b' */
  struct demo {          /* was 32 bytes, now 24 */
          int   a;       /*     0     4 */
          char  b;       /*     4     1 */
          char  d;       /*     5     1 */
          long  c;       /*     8     8 */
          int   e;       /*    20     4 */
  };
  • Packs by size, kills holes. Knows nothing about use.
  • Splits fields that travel together
  • Packs fields that contend
  • Open task: feed co-access + false-sharing into it

perf integration: finally real


  • Perennial request: pahole + perf together
  • Data-type profiling supplies access weights
  • pahole proposes cacheline groups
  • Flags false sharing
  • Full story: GNU Tools Cauldron talk

Recording: perf mem record



# perf mem record -- perf test -w false_sharing
[ perf record: Captured and wrote 5.520 MB perf.data (71250 samples) ]
# perf evlist
cpu/mem-loads,ldlat=30/P
cpu/mem-stores/P
  • Samples loads and stores with data addresses
  • Intel PEBS, AMD IBS, arm64 SPE
  • DWARF turns data addresses into types
perf's own false_sharing workload, shaped as a TCP connection: struct net_conn, 64-byte aligned. Cacheline 0: identity fields (read) and rx counters (written), the false-sharing line. Cacheline 1: tx and congestion fields, written. Cacheline 2: configuration, read only. Laptop i7-8650U, PEBS.

  • Loads (R) and stores (W) per member
  • Per cacheline summary: counts and periods
Same perf.data. Identity fields read only, rx counters written, same cacheline. After the struct, pahole prints a per-cacheline summary with nr_reads, period_reads, nr_writes, period_writes per member.

pahole + CTF: false sharing



$ perf data convert --to-ctf=./ctf.dir --data-type -i perf.data
$ pahole -F dwarf --perf-data-type=./ctf.dir -C net_conn ~/bin/perf
struct net_conn {
	...
	   >>> FALSE SHARING: cacheline 0: saddr / bytes_rx
	...
} __attribute__((__aligned__(64)));
  • Each CTF sample keeps CPU, time, data address
  • Same instance, other CPU, a write, within 10us
  • Per-member counts match the JSON path

What compilers could give us


  • perf rebuilds types: DWARF + disassembly
  • Coverage has a ceiling: unknowns remain
  • GCC keeps the field at final: MEM_EXPR
  • Ask: access records in the binary, like CO-RE
  • Full story: GNU Tools Cauldron talk
Condensed from the Cauldron talk: clang only has this as TBAA, gone under -fno-strict-aliasing; GCC keeps MEM_EXPR/MEM_OFFSET through the final RTL pass even with -fno-strict-aliasing.

One metric to remember



bad_addr: how much of a kernel profile is disassembled from text that never executed.

Ecosystem, not alone


  • libabigail abidiff: full ABI compat
  • codiff: lighter dump diff
  • gdb ptype /o (8.1): offsets in the debugger
  • dwgrep: query DWARF DIEs
  • DHAT: heap access histograms
  • Compilers emit BTF now (GCC -gbtf, LLVM -gbtf)
  • pahole still dedups/repairs

Lessons learned


  • Compilers are inconsistent: read the DWARF
  • Tools evolve at different rates (6 years of bpftool!)
  • Tests must be environment-aware
  • Dumps save hours of debugging

Future


  • Rust: niche layouts, const generics
  • Rust async fn: state machines
  • DWARF 6: new tags, adoption varies
  • BTF extensions for what C can't express
